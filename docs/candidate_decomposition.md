# Saved-array candidate decomposition

Generated by `python -B analysis/candidate_rank_v1/reanalyze_decomposition.py`.
The script reads saved CSV/NPZ data only. It does not load a simulator or model.

## Eligibility and definitions

- A branch is included only when `actual_25_complete=1`. There are 24,424 such
  branches among 25,228 saved branches. The 25th step must have a real post-step
  observation, rather than Isaac Lab's automatic reset observation.
- Reward sums use weights `0.99 ** k` for `k=0,...,24`. `dynamics_term` is the
  predicted reward-head sum minus the observed-latent reward-head sum.
  `head_term` is the latter minus the environment reward sum. The two terms add
  exactly to the model prediction minus actual environment reward. Predicted and
  observed head evaluations also differ in command inputs, so the first term is
  a latent-and-command-path term, not a pure dynamics causal effect.
- `value_dynamics_term` is predicted terminal value minus value-head output on
  observed latent. `value_head_term` is that observed value minus the terminal
  privileged expert critic output. Value quantities are raw (no discount).
- `horizon_summary.csv` contains undiscounted per-step errors for each kind and
  k=1,...,25. `step_decomposition.csv` contains every eligible branch and step.
- Full-set ranking uses only snapshots in which all 66 open-loop branches are
  eligible. Narrow-set ranking uses indices 0..32 and 65: mean plan, last 16,
  noise 0.1's 16, and base proposal. Top-eight overlap is an integer 0..8.
- Expert rank among 67 uses only snapshots where all 66 open-loop branches and
  the expert branch are eligible. Observed-latent total is observed-head reward
  sum plus `0.99 ** 26` times observed terminal value head output.
- Action RMS is computed over all 25 steps and 12 joints relative to the saved
  final mean plan. `action_rms_step_joint.csv` records RMS across branches for
  every step/joint cell. Closed-loop actions are the actions actually executed.
- Command MAE is averaged over 25 steps and three command components against
  the command sequence assumed by MPPI. `command_summary.csv` correlates this
  MAE with total reward bias. Its within-snapshot Pearson column is available
  only when a kind has multiple branches in a snapshot.
- Summary means and sample SDs use eligible branches as observations, except
  rank summaries, which use snapshots. Branches within a snapshot and snapshots
  within an episode are correlated. The estimates are descriptive.
- `group=near_fall_100` means the main episode fell within 100 measured steps
  after the snapshot. This group is small, so its results are supplementary.

## Main files

- `branch_decomposition.csv`: every eligible branch, all reward/value/action/
  command terms and the paths to the source CSV/NPZ files.
- `decomposition_summary.csv`, `value_summary.csv`, `action_summary.csv`,
  `command_summary.csv`: condition, group and candidate-kind summaries.
- `horizon_summary.csv`: condition, group, kind and step summaries.
- `rank_snapshot.csv`, `rank_summary.csv`: reward-head ranking decomposition.
- `expert_rank_snapshot.csv`, `expert_rank_summary.csv`: expert predicted and
  observed-latent total-score ranks.
- `audit.json`: CSV-versus-NPZ reconstruction and algebra checks.
